# 港航数字孪生决策系统组织责任与值守治理合同

本合同解决“功能很多，但谁负责、谁批准、谁执行、谁值班、事故向谁升级”没有形成可验证闭环的问题。它不会通过软件自行任命人员或分配权限，而是验证现场身份目录、正式责任分配、异人审批、培训资质、轮值交接和事件升级证据。

## 十二类责任领域

责任分配必须覆盖数据来源、模型风险、海事安全、码头生产运营、引航拖轮与航道服务、设备与控制工程、能源管理、网络与数据安全、事件指挥、业务收益确认、变更管理和管理层最终问责。

每个领域只能有一名最终问责人，同时至少有一名实际负责人、一名被征询人和一名被告知人。最终问责人与实际负责人必须是不同的实名目录人员，不能用部门名称、占位符或公共账号代替。

## 十项异人审批流程

固定流程包括数据合同变更、模型晋级、全链计划发布、执行配置变更、紧急停止、生产事件响应、回退放行、场站证据验收、业务收益声明和高权限访问变更。

除紧急停止外，所有流程均禁止紧急越权。每项流程都需要彼此不同的申请人、批准人、执行人和验证人，并至少有两名复核人；必须绑定变更单，且合同明确 `production_control_granted=false`。紧急停止可以先执行保护动作，但不能借此绕过后续事件指挥、审计和恢复放行。

## 三班值守、资质与升级链

每天分日班、晚班和夜班，值班经理、码头运营、海事安全、站点可靠性和网络安全五类关键岗位均需配置主岗、备岗和交接回执。主备人员必须不同，并持有覆盖完整轮值周期的对应培训或资质证据。

浏览器合同验证连续七天，共一百零五个班岗；正式现场验收验证连续二十八天，共四百二十个班岗。严重程度分为四级，确认时限分别为五、十五、三十和六十分钟，同时绑定事件指挥人、两级升级责任人和沟通方案。

## 正式验收边界

正式证据要求授权身份目录和轮值导出、四周完整记录、三名独立复核人——管理层最终问责、治理保证、海事安全——以及同一变更单。即使通过：

- `system_can_assign_roles=false`
- `self_approval_allowed=false`
- `dispatch_allowed=false`
- `production_authority=false`

这表示系统只验证组织与授权证据，具体账号、岗位任命和生产权限仍必须由港口的人力资源、身份与访问管理及业务授权系统正式授予。

## 生成与接入

```bash
python -m scripts.verify_operating_model_governance \
  --input /private/site/operating_model_input.json \
  --output /private/site/operating_model_evidence.v1.json
```

工具拒绝覆盖历史版本。生产环境通过 `PORT_DT_OPERATING_MODEL_GOVERNANCE_PATH` 接入经批准的证据。

接口：

- `GET /api/v3/operating-model-governance/readiness`
- `POST /api/v3/operating-model-governance/run`

浏览器运行不任命人员、不写入现场身份目录，也不接受批准参数。
