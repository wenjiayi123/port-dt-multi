# 首页启动与按页加载优化（2026-09-12）

桌面港口入口改为 `/#home-hero`。网页根路径也进入首页；模块深链接仍可直接使用。桌面配置位于 `dt-mobile-app` 仓库的 `tools/desktop_demo_center/configs/port.json`。

## 加载行为

- 首页先请求来源摘要，不再同时初始化五个能源模块及其他隐藏页面。摘要逐次读取来源与现场准入状态，RL 运行时和策略模型显示“按需核验”；点击对应卡片才加载完整证据。
- 相同且同时进行的 API GET 合并一次请求，响应分别克隆。写操作、取消信号、不同查询参数及身份上下文不合并。
- 各页面首次进入时加载数据；能源进度按当前页面的真实请求计算。返回后复用短期页面结果，刷新按钮重新请求；失败可重试，后台完成不会切换用户当前页面。
- 五个能源证据接口按输入文件状态复用已核验结果，并发首次请求只构建一次。输入、配置、模型、报告、历史指针或相关源码改变即重新执行原校验。校验失败或构建途中发生变化时，不返回上次成功结果。

完整证据接口和指标保留。缓存不授予现场执行权；摘要中的 `available: null` 表示尚未核验。此次不训练或替换正式策略，不修改冻结数据和模型。

## 实测结果

同一台 Intel i9-9880H / 16 逻辑核机器，基线为 `351d93a`。完整请求范围不变时，首次计算耗时基本相同；首页改善来自减少首屏所需请求，以及把完整核验延后至用户需要时执行。

| 同等请求范围 | 优化前首次 / 再次 | 优化后首次 / 再次 |
|---|---:|---:|
| 完整来源核验 | 36.956 s / 0.017 s | 35.246 s / 0.017 s |
| 五能源接口顺序读取 | 21.580 s / 0.368 s | 21.236 s / 0.238 s |
| 原 16 个完整接口并发 | 31.230 s / 0.625 s | 31.227 s / 0.540 s |

| 模块 | 优化前再次读取 | 优化后再次读取 |
|---|---:|---:|
| 堆场照明 | 11 ms | 29 ms |
| 暖通空调 | 16 ms | 43 ms |
| 岸电储能 | 303 ms | 97 ms |
| 储能能量调度 | 22 ms | 30 ms |
| 场桥作业 | 14 ms | 37 ms |

五模块重复读取合计减少约 35%；依赖检查使部分原本很快的接口增加了几十毫秒，完整响应 SHA 均保持一致。新的首页摘要首次请求为 **3.63 ms / 5,887 字节**；完整来源为 236,951 字节，两者内容范围不同，不能解释为完整模型核验只需数毫秒。

46 次业务 GET 均返回 200。五能源接口在首次、再次和并发对照中的响应 SHA 全部与基线相同。测试副本不含 95 个原始模型文件，只使用 83 个公共模型副本。

## 验证

461 项 Python 测试及 15 组 JavaScript VM 脚本通过；编译、固定业务指标核验、发布门禁、隐私扫描和两套公共模型导出校验通过。临时烟雾测试覆盖 12 种方法各 64 步，不作为正式训练结果。

真实浏览器验证根路径进入首页、7 张来源卡片、五个能源页面首次进入和刷新、加载中返回首页、跨卡片核验完成、模型原始 JSON、图表绘制及 Twin 3D。五个未打开模块在首页保持 `idle`，当前页面无虚假的 `0/5` 等待；验收页控制台没有警告或错误。未将工具调用耗时当作浏览器完整加载时间。

## 复测方法与边界

使用独立公开模型副本、新 Python 进程、同一依赖环境。每个版本使用新的输出目录，按 `provenance → energy → homepage → provenance-summary` 顺序测量；不额外预热字体缓存。`homepage` 是固定 16 个完整 API 的压力对照，并非优化后首页实际请求集合。旧版本仅执行前三项。

```bash
PORT_DT_PROFILE_OUTPUT=$(mktemp -d /tmp/port-startup-profile.XXXXXX)
for phase in provenance energy homepage provenance-summary; do
  python scripts/profile_startup_loading.py --repo . \
    --output "$PORT_DT_PROFILE_OUTPUT" --phase "$phase"
done
```

macOS 可增加 `--read-only-sandbox`，禁止测量期间写入被测副本；输出目录必须位于副本之外，运行所需的空目录应预先存在。脚本记录响应状态、字节数和 SHA、并发健康检查耗时、输入版本及字体缓存状态。

“首次”仅表示新服务进程，不代表清空操作系统文件缓存；单次测量不是 P95 或性能保证。一次中间试验改变了阶段顺序，把 macOS 字体枚举约 21.6 秒的首次开销从完整来源接口转移至岸电接口。该试验已保留并标记为混杂，不作为提速或退化依据；同条件分析中新旧版本均出现该开销。

服务进程到健康响应的观测约为 3.0 s → 3.6–3.7 s；基线副本已有 Python 字节码缓存，优化副本没有，因此不据此声称进程启动提速或回退。优化重点是首页不再争用完整训练证据的加载资源。
