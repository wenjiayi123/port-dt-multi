# 真实业务收益归因闭环

## 目标与证据边界

本模块回答的不是“仿真里节省了多少”，而是“某一已批准建议在现场实际执行后，相对同期既有方案产生了多少可复核收益”。它把预测不确定性、影子运行、执行验收和六方靠泊协同证据摘要绑定到同一次归因运行，并保留建议回执、人工批准回执、实际计划、执行回执、后验计量来源、同期对照和复核结论。

仓库原有 [离线业务指标基准](BUSINESS_KPI_BENCHMARK.md) 继续作为公开数据反事实和确定性调度结果，不修改其样本、摘要、历史文件或结论，也不把它改称现场业务收益。浏览器中的合同样例同样只验证数据结构、计算和门禁，不形成现场收益声明。

即使现场证据通过，系统仍保持：

- 不自动承诺泊位、引航、拖轮、岸桥、能源或检修资源；
- 不自动下发设备命令；
- 不取得生产控制权；
- 结论只适用于注册协议、观测窗口、执行范围和场站，不外推为全港通用因果结论。

## 固定业务指标

一次归因必须同时提交以下八类结果，不能只选择有利指标：

| 指标 | 计算口径 | 收益方向 | 业务含义 |
|---|---|---|---|
| 能源费用 | 能源消耗量乘以同期电价 | 越低越好 | 核验实际能源账单口径，而不是模型内部奖励值 |
| 平均等待时间 | 船舶或作业任务的实测等待分钟数 | 越低越好 | 覆盖锚地、航道、泊位和作业衔接造成的等待 |
| 泊位利用率 | 泊位有效作业分钟数除以可用分钟数 | 越高越好 | 防止只通过延长占泊时间制造表面吞吐 |
| 集装箱吞吐量 | 同口径窗口内完成的标准箱数量 | 不得劣于既有方案 | 作为非劣门禁，防止以牺牲主业换取单项节能 |
| 碳排放量 | 能源消耗量乘以同期排放因子 | 越低越好 | 与能源计量和排放因子版本同时留痕 |
| 设备非计划停机 | 非计划停机分钟数 | 越低越好 | 检查策略是否把压力转移到设备可靠性 |
| 设备维护费用 | 同口径维护工单与费用汇总 | 越低越好 | 防止短期节能造成后续维护成本上升 |
| 监管作业延误 | 监管环节造成的实测延误分钟数 | 越低越好 | 覆盖申报、查验、放行等对生产节奏的影响 |

每个观测单元还必须提交货量、船型规模、天气严重度、潮位、班次和设备可用率六项匹配因素，以及能源计量、码头生产系统、排放因子、维护、监管和安全六类来源引用。

## 归因设计与执行绑定

支持三种预先声明的方法：随机对照试验、阶梯式分期推广、匹配双重差分。无论选择哪种方法，都必须满足：

1. 分析协议和分析计划在分组前登记，并保存安全散列摘要；
2. 明确干预边界、干预前窗口、干预后窗口和分组依据；
3. 每个独立配对都包含候选组干预前、候选组干预后、既有方案组干预前、既有方案组干预后四个完整单元；
4. 四个单元都必须有实际计划引用和唯一执行回执；
5. 只有候选组干预后单元可以标记为执行候选建议，并且必须同时绑定建议回执、人工批准回执和建议内容摘要；
6. 结果必须在执行之后由固定来源计量，不接受模型预测值冒充实测值；
7. 所有同期系统变更、安全事件和额外干预都必须保留，不能从失败结果中删除。

每个配对、每项指标的双重差分为：

```text
候选组变化 = 候选组干预后结果 - 候选组干预前结果
既有方案变化 = 既有方案组干预后结果 - 既有方案组干预前结果
双重差分 = 候选组变化 - 既有方案变化
```

对于能源费用、等待、碳排放、停机、维护费用和监管延误，系统把下降转换为正收益；对泊位利用率和吞吐量，系统把上升定义为正收益。随后以完整独立配对为抽样簇，执行一千次成对簇重抽样，给出平均收益及百分之九十五置信区间。

匹配双重差分仍依赖平行趋势和没有未记录同期干预的假设，不能证明所有未观测混杂均已消除。现场条件允许时，应优先采用随机对照或预先登记的阶梯式分期推广；无法随机时，应通过趋势检查、敏感性分析和业务复核补强证据。

## 固定通过门槛

归因状态只有在以下条件同时满足时才通过：

- 主指标相对收益的百分之九十五置信区间下限大于零；
- 吞吐量相对变化的百分之九十五置信区间下限不低于负百分之二；
- 六项匹配因素的最大标准化差异不超过零点二五；
- 实际执行回执覆盖率、结果来源覆盖率、候选建议实际执行符合率均为百分之百；
- 安全事件数量为零；
- 同期额外干预数量为零。

合同样例至少需要十二个完整配对、四十八个执行单元。现场收益声明至少需要三十个完整配对、一百二十个执行单元，并且来源必须属于已授权现场导出、完成来源证明、通过全部门槛，再由业务责任人、运营保证复核人和因果方法复核人三方独立签署；三人必须互不相同、不得与数据责任主体相同，并绑定稳定变更单。

门禁失败不会删除计量结果。系统保留失败指标、同期干预、安全事件、置信区间和数据质量信息，以便审计，而不是只保留“节省成功”的运行。

## 命令行生成现场证据

输入文件必须使用 `business_benefit_attribution_dataset.v1` 合同。以下命令只写入一个从未存在的新版本文件；目标文件已存在时会拒绝覆盖。

```bash
.venv312/bin/python scripts/verify_business_benefit_attribution.py \
  --input /absolute/private/path/business_benefit_dataset_v1.json \
  --output /absolute/private/path/business_benefit_evidence_v1.json \
  --authorized-source-attested \
  --business-owner-approved-by benefit-owner-reviewer \
  --operations-assurance-approved-by operations-assurance-reviewer \
  --causal-methods-approved-by causal-methods-reviewer \
  --change-ticket benefit-review-ticket-001
```

现场部署以私有路径接入证据：

```bash
export PORT_DT_BUSINESS_BENEFIT_ATTRIBUTION_PATH=/absolute/private/path/business_benefit_evidence_v1.json
```

服务会重新验证固定指标合同、明细和汇总摘要、执行覆盖、固定门槛、三方复核、变更单及证据摘要。仓库不附带伪造的通过文件。

## 页面按钮顺序

1. 点击“刷新归因状态”：查看现场证据是否配置、是否有效，以及当前是否具备本站点收益声明资格。
2. 点击“查看归因合同”：核对三种设计方法、八项业务指标、六项匹配因素、六类结果来源、四项上游绑定和固定门槛。
3. 点击“运行成对归因”：运行十二个配对、四十八个执行单元的合同样例，查看实际执行覆盖率、主指标收益及置信区间、吞吐非劣和同期干预门禁。

页面必须始终显示“合同样例不等于现场已实现收益”。浏览器接口不接收现场来源证明和三方批准参数，不保存证据，也不改变真实计划。
