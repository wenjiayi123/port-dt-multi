# 岸电储能 V8：增碳根因与可行性审计

本次复算确认：截图中的 **年化增碳 252.433565 吨** 是原 V3.1 策略真实的场景核算结果，不是正负号显示错误。主要原因是“低价时段高碳、高价时段低碳”的合成数据关系、储能损耗，以及只模仿经济规则的训练目标。V8 应在相同数据和设备条件下纠正策略、约束与评估；不能通过改变碳因子、提高设备效率或删除失败记录来制造更大的收益。

这些数值都是公开数据校准工程场景结果。电价、碳因子、负荷和柔性任务并非上海港 EMS/TOS 实测数据，不能解释为现场减排、利润、账单或生产准入。

## 1. 把 252.4 吨增碳逐项对账

复算对象是既有 [V3.1 报告](../evidence/v3/shore_bess/runs/shore-bess-v3-safe-20260813T015000Z/report.json) 中三个已保存的模型和原 20 个 168 小时窗口。使用已公开的旧测试段仅用于追溯旧结果，未进入 V8 参数选择。逐窗明细保存在 [历史碳核算分解](../evidence/v8/shore_bess/audits/v31-historical-carbon-decomposition-20260912.json)。

| 三种子、20 窗口的周平均 | 复算值 |
|---|---:|
| 充电电量 | 63,772.904211 kWh |
| 放电电量 | 58,773.108521 kWh |
| 充放电损耗 | 4,999.795690 kWh |
| 充电加权碳因子 | 0.585432336 kg/kWh |
| 放电加权碳因子 | 0.552920717 kg/kWh |
| 损耗引起的增碳 | 2,927.042069 kg/周 |
| 充电与放电碳强度错配引起的增碳 | 1,910.808926 kg/周 |
| 柔性负荷净碳变化 | +0.027055 kg/周 |
| 合计增碳 | **4,837.878049 kg/周** |
| 按 365.25 / 7 外推的增碳 | **252.433565 t/年** |

分解恒等式为：

```text
ΔCO₂ = charge_kWh × charging_factor − discharge_kWh × discharging_factor + flex_ΔCO₂
     = (charge_kWh − discharge_kWh) × charging_factor
       + discharge_kWh × (charging_factor − discharging_factor) + flex_ΔCO₂
```

代码按执行后的 PCC 购电功率核算碳，并将最终 SOC 和柔性 backlog 恢复到初值，因此这次负结果不是靠耗尽电池库存或不归还任务产生的：见 [旧环境 step / terminal accounting](../app/services/rl_model/shore_bess/v3_environment.py)。旧报告的降本 **0.6480095%**、降峰 **1.4363992%** 与增碳 **0.2189481%** 同时成立，不能用经济门槛通过来替代综合门槛。

## 2. 数据集存在结构性的价格—碳冲突

[生成器 `_build_rows`](../scripts/fetch_shanghai_public_dataset.py) 第 261–263 行固定设置：

```python
price = 0.43 if hour < 7 else (1.08 if 17 <= hour < 22 else 0.72)
carbon = 0.565 + 0.025 * sin(2 * pi * (hour + 3) / 24)
```

谷价 00–06 时的碳因子为 **0.582678–0.590000**；峰价 17–21 时为 **0.543349–0.565000**。旧训练段中电价与碳因子相关系数约 **−0.676**。低价充电、高价放电正好将电量从较低碳时段移到较高碳时段。

原 [设备参数](../config/shore_bess_v3.json) 是 **50,000 kWh / 4,000 kW**、充电效率 **0.96**、放电效率 **0.96**，往返效率为 **92.16%**。即使每次都在全天最低碳 **0.54** 时充电，交付 1 kWh 的碳也至少为：

```text
0.54 / (0.96 × 0.96) = 0.5859375 kg/kWh
```

它只略低于最高碳 **0.59**；每个最终交付 kWh 的理论最优减碳比例仅 **0.688559%**，而且低碳充电时电价为 0.72，高碳放电时电价为 0.43，方向与套利相反。这个比例还是“被储能转移的电量”的界限，不是全港总电量的减碳比例。

往返效率不能通过随意调高来解决该问题。[NREL 2024 ATB 商用储能](https://atb.nrel.gov/electricity/2024/commercial_battery_storage) 将往返效率定义为有用输出与输入电量之比，其代表性研究假设为 85%。这里只用该来源校验概念；本实验继续保留原场景 92.16%，不把文献假设当成本设备实测参数。

## 3. 网络在学习什么，比加深网络更关键

[旧训练器](../scripts/train_shore_bess_v3_safe.py) 使用 PPO 的 MLP 作为模型容器，但第 172–183 行实际反向传播的是 **teacher action MSE**。它没有使用环境奖励来更新策略梯度；34 维状态、2 维动作和 128×128 隐层的大小不能改变这个事实。

| 审计项 | 旧版实现与影响 |
|---|---|
| 教师 | [峰谷规则](../app/services/rl_model/shore_bess/v3_environment.py) 以电价与负荷判断 BESS 动作，柔性动作恒为 0。它本身没有碳优化目标。 |
| 梯度目标 | 克隆教师动作均方误差。配置里的碳奖励权重不会进入这个 MSE 损失。 |
| checkpoint 选择 | 旧训练器第 210–219 行在安全通过后选择验证成本最低者，没有碳不回归约束。 |
| “3/3 收敛” | 第 234–253 行判断模仿损失降低与验证成本平台期。它证明拟合稳定，不能证明 RL 收敛或降碳。 |
| 柔性动作 | 旧报告每周实际绝对移位仅约 7.47 kWh，第二个动作几乎没有学到业务作用。 |
| V3.2 后续尝试 | 已经提高碳权重并加入综合准入，但失败候选依然应保留。单独调权重不能突破数据与效率共同决定的可行域。 |

V8 的有效改进需要真实环境交互、真实优化器更新记录、与模型权重绑定的训练日志，以及在同等安全投影下对照零动作、规则、历史策略和未训练网络。规则或 LP 的收益必须单独列示，不得放进神经网络效果一栏。

直接反序列化旧产物还发现参数声明与执行不一致：V3.2 `seed_43/ppo_step_30000.zip` 实际为 **30,240 环境步、学习率 0.0003、熵系数 0**，对应配置声明却是 **0.00015、0.001**。后来的脚本修正不能追溯性改变旧权重。V3.1 克隆模型的 `num_timesteps=0`、PPO `_n_updates=0`；记录中的 15,840 次更新属于监督 MSE 的 Adam 步。

V7 岸电专项确实完成过 **630,000 环境步、154,500 优化更新、12 种子运行**（SAC 三种子、三组 DQN 共九种子），全部没有通过综合准入。因此问题不能解释成“没有训练”或“把网络加深就会成功”。旧 V3.2 连续 PPO 的初始 `log_std=[0,0]` 还对应全动作量程的探索标准差；过大的探索与高投影率一起削弱了可学习的动作差异。

V8 的训练器逐个记录实际模型超参数、网络结构、初始/最终权重摘要和 PyTorch 优化器 `step` 调用次数。PPO 的 `_n_updates` 是 epoch 计数，SAC/TD3 的计数是梯度迭代，不能把它们直接当成同一种优化器次数。SAC 的 actor/critic、TD3 的 actor/critic 分开计数。

## 4. 数据隔离与任务约束还需修正

- **来源颗粒度：** [数据卡](DATASET_CARD_public_cn_sha_hourly_v3.md) 的 17,544 小时来自 22 个官方吞吐统计期与小时级气象/海洋再分析；负荷、到港、电价、碳因子、设备状态等是派生工程特征。17,544 行不能解释为 17,544 条独立现场调度因果样本。
- **分组隔离：** 旧 70/10/20 切分点在 2025-05-26 和 2025-08-07。同一月份的派生小时共享月度总量与全月归一分母，跨 split 重复共享来源锚。V8 使用完整来源月：训练 **2024-01—2025-04（11,664 行）**；验证 **2025-05—07（2,208 行）**；重复测试 **2025-08—12（3,672 行）**。已被旧实验看过的后段明确称为重复测试，不能重新命名为从未打开的盲测。
- **归一化：** 旧环境第 236–245 行确实只从训练切片获取尺度，未发现全量 scaler 泄漏。V8 应继续把训练切片显式传给验证、测试环境。
- **时区：** CSV 的时间是 UTC，但旧生成器直接取 UTC `hour` 定价；旧环境也直接取 UTC `hour` 匹配 `critical_hours_local`。不能把这个时钟设定称为上海当地真实峰谷电价。原 benchmark 保持冻结，现场适配或新数据版本应明确转换为 `Asia/Shanghai`，并重新标定、训练和对照，而非只修界面时间。
- **柔性截止期：** 旧环境只有 backlog 总量与周末清零，没有任务年龄；SLA shortfall 又被固定为零，无法检验任务是否已延误。V8 已加入12个 FIFO 年龄桶、最长12小时恢复、逐步恢复功率约束和独立到期违约计数，防止通过无限延迟工作获得收益。
- **物理投影：** 旧版先作功率/爬坡限制，再作末端 SOC 修正，后者可能改变先前受限动作；公共默认场景零违约不等于极端状态也安全。V8 已对最终执行动作核验 SOC、设备功率、备用、PCC 和爬坡共同可行性，边界数值问题的修复与压力验证见第7节。

## 5. 训练前先计算可行上界

[可复现审计脚本](../scripts/audit_shore_bess_v8.py) 使用训练期内六个 168 小时窗口，固定原数据、资产、效率、费用与 SOC 末端约束，求解完整未来已知的线性规划。输出与来源 SHA-256 位于 [按完整来源月隔离的 LP 报告](../evidence/v8/shore_bess/audits/train-feasibility-20260912-v8-r1.json)。

| 训练窗口中的乐观 oracle | 成本降低范围 | 碳降低范围 | 峰值降低范围 |
|---|---:|---:|---:|
| 只优化成本，要求峰值不升 | 1.0454%—1.2603% | **−0.2690%—−0.2424%** | 0.7256%—5.4364% |
| 成本最优，碳与峰值不得回归 | 0.1781%—0.2848% | 约 0%，卡在碳约束边界 | 0.7256%—2.6878% |
| 碳最优，成本与峰值不得回归 | 约 0%，卡在成本约束边界 | **0.01489%—0.02132%** | 0.5147%—1.5000% |
| 关闭 BESS，仅柔性负荷，碳与峰值不得回归 | 0.1728%—0.2077% | 约 0% | 0.5269%—0.9312% |

数值范围是六个预先等距选择训练窗口的范围，不是置信区间，也不是整个数据集的普遍定理。LP 忽略温度/SOH 非线性，并没有加入 V8 的 12 小时 FIFO 截止期，因此是偏乐观的诊断界限。其安排按旧环境逐时执行后大体复现，仍然只说明完整未来已知时的可行性；不能作为可部署策略、RL 指标或新模型的准入证明。

结论是：**原数据条件下，同时得到“大幅降本、大幅减碳、大幅降峰”不现实。** 有研究价值的结果应是保留原始失败证据，证明神经策略在有期限、有损耗、同等安全约束下把增碳扭转为稳定非增碳或小幅减碳，并报告与强基线的增量及不确定性。最终 V8 模型是否做到，必须由独立的训练与冻结评估产物判定，不能用此 oracle 代替。

## 7. 修正训练中的数值误罚与边界可行域

[执行数值审计](../evidence/v8/shore_bess/audits/physical-execution-numeric-audit-20260912.json) 追溯到两项可复现问题：物理功率被重复转成 float32 后，边界处出现最高约 **0.216 W** 的爬坡超限；过于保守的制动公式又把允许跨零的充放电动作误判为空集。这些细小误差会触发每次 **100 个缩放奖励单位**的处罚，足以污染价值网络。它们不属于实际大功率设备失控。

V8 将最终物理功率到执行端的交接保留为 float64，修正双向制动边界，并仅在浮点舍入量级合并相邻区间。神经网络仍使用 float32，原物理违约容差和旧 V3 源码保持不变。固定 **120 个训练集周窗口、20,160 步**的饱和、交替和随机动作压力验证中，物理违规、空可行域、SOC/截止期/末端库存违规均为零。

含旧误罚的 TD3 多步 r3 已终止并保存中止说明、检查点与日志。修复后从随机初始化重训 r4；不能把旧权重放到新环境的复算当成训练收益。该修复证明执行与奖励账本更可信，业务效果仍须由新模型验证。

## 8. 仅用训练段检查标量目标与减碳要求是否一致

[目标权重审计脚本](../scripts/audit_shore_bess_v8_objective.py) 只解析 CSV 前 **11,664 条训练记录**，沿用六个预先固定窗口，分别求解完整 BESS+flex 与仅 flex 的 `真实电费、损耗和需量成本增量 + λ × 碳增量`。扫描值固定为 **8、12、16、20、30、40 元/kg**，不预加成本、碳或峰值非回归约束。逐窗成本、碳、峰值、加权目标和完整小时计划保存在 [72 个 LP 的目标扫描报告](../evidence/v8/shore_bess/audits/train-scalar-objective-audit-20260912.json)。

r5 依据训练段扫描确定并以 CLI 启动的参数为：**λ16、seed 912、SAC 与 TD3 各 60,000 环境步、标准一步 replay（无 n-step）**，共用已修复并冻结的物理环境，从随机初始化开始。λ 的选择仅依据这份训练段扫描，不按验证、重复测试或前向结果挑权重。r5 的学习、验证和准入结果独立记录；若这两次探索均不合格，保留失败证据，不追加按验证结果调权的尝试。单种子 pilot 和上述 LP 均不构成三种子正式准入。

[r5 独立协议登记](../evidence/v8/shore_bess/audits/r5-preregistered-protocol-20260912.json) 实际写于 **2026-09-12 03:24:24 UTC**，晚于训练启动；登记时已存在 SAC 10k、TD3 10k/20k 检查点，文件明确记录 `strict_preregistration_before_training=false`，不能称为严格事前注册。该登记绑定训练目标扫描、训练源码及两个运行的 config/manifest SHA，并指定最终 60k 检查点作算法对照；通常的验证集选模规则与全部准入门槛保持原样。
