# 港口全链条跨资源滚动协同证据合同

本合同解决“各业务域都有局部策略，但没有一张可复核的港口全链计划”的问题。它把船舶到港、航道通行、靠泊、装卸、水平运输、堆场、闸口、铁路和维修放在同一时间轴上，生成一个容量可行、冻结承诺不变、前后工序可交接的候选计划。候选计划始终是建议，不会写回现场共享计划、承诺真实资源或控制设备。

## 固定业务范围

每条业务链必须完整覆盖九个阶段：船舶到港、航道与引航拖轮、靠泊与系泊准备、岸桥装卸与岸电、水平运输交接、堆场作业、闸口疏运、铁路疏运和设备维修窗口。

所有任务合计必须实际使用十一类资源：航道窗口、泊位、引航员、拖轮、岸桥、水平运输车辆、堆场箱位、闸口通道、铁路作业窗口、岸电与储能容量、维修班组。每项资源必须提供容量、固定单位、全时域可用窗口、责任主体、来源引用和安全联锁引用；每项任务必须绑定原计划资源分配、原计划回执、预测回执和业务来源引用。

## 固定规划规则

- 时间粒度为十五分钟，决策后前三十分钟为冻结窗口；冻结任务的开始时间和资源分配不得变化。
- 有前后关系的任务至少保留十五分钟交接缓冲，并且依赖图必须无环、不得跨业务链倒序引用。
- 单项任务相对原计划最多顺延一百八十分钟，且不得超出截止时间或七十二小时以内的规划时域。
- 固定目标权重为船货延误百分之三十五、计划稳定性百分之二十、能源峰值百分之十五、资源均衡百分之十五、维修风险百分之十五。
- 求解器按冻结状态、业务优先级、依赖拓扑和原计划时间依次寻找最早可行容量。它是确定性的启发式求解器，不宣称得到全局最优解；输入相同必须产生相同候选摘要和建议回执。
- 原计划容量冲突会完整保留为证据；候选计划必须做到全部任务可排、容量冲突为零、截止时间违约为零、冻结任务变化为零、前后工序违约为零、安全事件和未解决异常为零。

## 证据等级与批准

浏览器合同样例采用两条业务链，只用于验证冲突传播、容量求解和证据生成。正式现场证据至少包含十条独立业务链，数据来源必须是获授权的现场统一计划与资源导出，并同时绑定现场孪生标定、靠泊协同、预测不确定性、执行放行和业务收益归因五项上游证据摘要。

进入生产场站就绪门还需要四名彼此独立且不属于数据责任主体的复核人：综合计划、海事服务、码头运营、设备与能源，并绑定一个稳定的变更单。即使全部通过，边界仍固定为：

- `recommendation_only=true`
- `shared_plan_mutated=false`
- `automatic_resource_commitment_allowed=false`
- `dispatch_allowed=false`
- `production_authority=false`

这表示证据只证明候选计划符合固定合同，不代表泊位、引航、拖轮、岸桥、车辆、铁路或电力资源已经被责任系统接受。真实资源承诺仍必须由各业务责任系统和现场人员分别确认。

## 生成与接入

```bash
python -m scripts.verify_end_to_end_coordination \
  --input /private/site/end_to_end_coordination_input.json \
  --output /private/site/end_to_end_coordination_evidence.v1.json
```

授权现场运行须额外提供来源核验声明、四名复核人和变更单参数。工具只创建新版本文件，目标已存在时拒绝覆盖。经验证的文件通过 `PORT_DT_END_TO_END_COORDINATION_PATH` 接入；仅设置路径、复制合同样例或自行修改摘要都不能通过就绪门。

接口：

- `GET /api/v3/end-to-end-coordination/readiness`：查看合同、证据和失败关闭状态。
- `POST /api/v3/end-to-end-coordination/run`：运行无副作用合同求解。浏览器接口固定不接受来源核验或批准参数。
