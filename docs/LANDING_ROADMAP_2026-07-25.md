## 2. 分阶段步骤

### 阶段A：稳定换港契约

1. 建立 `config/ports/*.json` 场景包。
2. 场景包登记港口代码、时区、货币、资产容量、动作上下界、目标权重、因素要求和校准状态。
3. `control_authority` 在开源配置中固定为 `recommendation_only`。
4. 数据上传继续要求显式字段映射、许可、所有者、时区、用途和SHA-256。

验收：换数据集与场景包即可启动研究/影子评估；缺场景、缺必需因素或质量失败时拒绝训练。

### 阶段B：扩展现实因素、观测与动作

`port_ops_v2` 采用37维观测：

- 13个既有时钟、规范数据和内部状态；
- 12个国际港口现实因素；
- 12个逐因素可用性掩码。

现实因素包括风速、能见度、浪高、流速、泊位占用、堆场占用、岸桥可用、设备可用、航道拥堵、冷藏箱负荷、引航/拖轮可用和关闭状态。缺失因素使用中性值加零掩码，不编造观测。

新动作是5维建议量：BESS功率、服务强度、柔性负荷、泊位优先级、堆场流量。DQN使用显式离散格点；其余RL使用连续动作；MPC对新增调度量保持中性基线。所有动作仍只形成建议。

### 阶段C：提高公开数据有效信息量

保留 `public_port_ops_v1` 作为新加坡长时段、聚合锚点和固定业务KPI对照。新增 `public_us_la_6min_v1`：

- 美国交通部BTS洛杉矶港月度TEU；
- NOAA洛杉矶站6分钟验证水位；
- NOAA圣莫尼卡站6分钟气温和风速；
- 一年87,459个训练时步；
- 262,347条独立原始公共观测；42条短缺口插值单独计数；
- 派生列、缺失因素和来源逐字段登记。

来源：

- [BTS Monthly TEU Data](https://data.bts.gov/Maritime-and-Waterways/Monthly-TEU-Data/rd72-aq8r)
- [NOAA CO-OPS Data API](https://api.tidesandcurrents.noaa.gov/api/prod/)
- [NOAA/MarineCadastre 2024 AIS archive](https://coast.noaa.gov/htdata/CMSP/AISDataHandler/2024/index.html)

AIS年度归档超过100 GB，不能直接提交到Git。项目应提供可复现流式过滤入口，由使用者按港区边界构建本地包，并在元数据中保存原文件哈希、边界、日期和筛选规则。

### 阶段D：正式训练与比较

1. 六种RL每种至少3个随机种子。
2. 每次至少10,000真实优化步；MPC使用同留出窗口。
3. 训练段不渲染；评测只读取时间顺序留出段。
4. 保存模型、配置、数据哈希、实现版本、随机种子、优化器历史、测试轨迹和95%区间。
5. 同时报告奖励、能耗成本、碳排、吞吐、峰值、延迟和护栏违规率。
6. 只有 `multi_seed_ready=true` 才允许写比较性结论。

短步数烟测继续保留，但标签固定为 `RL_SMOKE_WIRING_ONLY`。

### 阶段E：前后端与小懿联动

RL页同屏展示：

- 训练中心；
- 七算法矩阵和真实实现；
- 目标函数、37维观测和5维动作；
- 数据包行数、独立观测、来源等级、因素覆盖和哈希；
- 小懿Q版训练顾问；
- “刷新后端证据”“小懿解读训练门禁”“打开小懿全系统助手”按钮。

显示内容来自 `/api/rl/engine/capabilities`、`/api/rl/datasets` 和
`/api/rl/benchmarks/summary`，不使用前端随机数生成成绩。

### 阶段F：真实港口接入与生产门槛

技术HR下载后可直接运行公开研究链路；接入真实港口时需要替换：

1. TOS/AIS/PCS/EMS/BMS/设备/气象/潮汐/电价数据映射；
2. 现场资产铭牌、泊位/航道规则、SLA、天气停工线和安全包络；
3. 港区布局、实体ID和数字孪生标定；
4. 数据许可、留存、隐私和审计策略；
5. 影子运行、多季节回测、故障注入、人工接管和回滚演练；
6. 独立PLC/EMS联锁与变更审批。

这些条件未完成时，项目的准确定位是“可公开、可复现、可接港的研究与集成平台”，不是已经投产的自主控制器。
