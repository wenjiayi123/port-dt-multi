# 二十四小时连续运行与灾备证据合同

本合同把“应用能够启动”与“具备现场连续运行能力”分开。进程存活、一次健康检查、公开数据回放或软件演练都不能单独形成生产服务等级承诺；必须提供连续时间序列、组件服务目标、事件闭环、每日备份还原、变更回退和故障恢复演练的同站点证据。

## 连续观测范围

每个小时必须同时覆盖八个核心组件：应用程序接口网关、决策建议服务、数字孪生运行时、现场数据接入、事件消息队列、审计证据存储、遥测时序存储和运营人员界面。每个组件记录可用分钟数、请求量、错误数、响应时延百分位、数据新鲜度百分位、预期与送达审计事件数以及来源引用；任意小时或组件缺失都会拒绝数据包。

固定服务目标为：

- 可用率不低于百分之九十九点九；
- 错误率不高于百分之零点一；
- 响应时延百分位不高于一千毫秒；
- 数据新鲜度百分位不高于一百二十秒；
- 审计事件送达率为百分之百。

浏览器合同样例需要连续一百六十八小时，正式现场验收需要连续七百二十小时。合同按每个组件独立计算门禁，不能用一个高可用组件掩盖另一个组件的失效。

## 事件、备份和恢复演练

每个事件必须包含发现、确认、缓解、恢复、关闭的有序时间线，并绑定事件指挥人、工单、根因和复盘引用。每个自然日必须至少有一份不可变、加密、带安全散列的备份，并在导出截止前完成真实还原测试。

六类固定演练必须全部通过：进程重启、可用区切换、数据库还原、消息积压恢复、凭据轮换和安全降级。每类演练都有固定的恢复时间目标和恢复点目标，必须绑定执行、还原与批准回执。所有变更还需要批准、灰度健康检查和可用回退回执。

## 正式验收边界

正式证据要求授权现场导出、三十天连续窗口、三名彼此独立且不同于数据责任人的复核人——服务责任人、站点可靠性责任人、连续性与网络安全责任人——以及同一变更单。即使通过，边界仍固定为：

- `automatic_failover_authority=false`
- `dispatch_allowed=false`
- `production_authority=false`

这表示证据允许在限定场站和限定观测窗口内声明服务目标已被验证，但不能使本系统自行切换基础设施、修改资源或控制港口设备。

## 生成与接入

```bash
python -m scripts.verify_production_continuity \
  --input /private/site/production_continuity_input.json \
  --output /private/site/production_continuity_evidence.v1.json
```

工具只创建新版本文件并拒绝覆盖。生产环境通过 `PORT_DT_PRODUCTION_CONTINUITY_PATH` 接入经批准的证据。

接口：

- `GET /api/v3/production-continuity/readiness`
- `POST /api/v3/production-continuity/run`

浏览器运行固定不接受现场来源核验或批准参数。
