## 确认的数据口径与前端反馈

首页来源卡此前取 `provenance.rl.datasets[0]` 并标成“数据集”，第一项恰为 forward；该 API 实际提供可用目录，并未表示正在用它训练。已向主任务提供代码位置，将目录标签与当前策略/训练数据区别展示。

曲线旧通用点位键 `kW` 仍用于能耗/碳强度序列，但响应的 `unit` 明确为 `kWh/TEU` 或 `kgCO2e/TEU`，数值按该单位核算。现场未接入能力、旧停用按钮与遗留外部接口候选路径均向浏览器验收代理交接，不能仅因源码含字符串就宣称发生了用户可见 404。

## 最终复测与冷启动补查

重启后再次并发读取 readiness、来源与数据质量，10 次独立 liveness 全部 200（最慢 0.502 秒）；真实配置缺失的船期请求含正确 start/end 后返回 503（0.034 秒）。正确整数月份进一步发现 ESG breakdown 把无数据包装为 500；已改为 `available=false` 和空数值，保留缺失口径，2 项真实路由/服务回归通过，等待最终统一 reload 的现场确认。

额外用冷进程重放并抓取 Python 主线程栈，确认 `/api/rl/datasets` 首次同步扫描 8 份 CSV 占用事件循环约 9.99 秒；同批 actuator 请求也被延迟约 9.98 秒。目录接口已移至后台线程，并有专门并发回归。证据聚合冷加载约 37.28 秒，其中目录扫描结束后主线程在 selector 等待，后续模型读取在 worker 执行。性能结论保留冷启动与缓存后的区别，不用放大超时掩盖阻塞。

V3 端点线程修复保留原 Python async 契约；针对直接调用与真实 ASGI 并发的 11 项回归通过。第一轮探针和后来发现的故障记录均保留，不倒改早期结果。

最终统一 reload 后，真实8099目录接口200（0.078秒）、未配置船期503（0.055秒）、缺失ESG月份200/available=false/数值null（0.052秒）。同批10次liveness全部200，最慢0.0535秒。公开摘要见 `evidence/public_models/verification_20260912/final_http_acceptance.json`；完整发布门与模型验证记录见同目录 `report.json`。
